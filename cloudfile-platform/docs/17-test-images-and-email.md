# 17 — Testing Image Upload & Real Email (step by step)

A focused, copy-paste guide to:
1. Upload a real **image** and download it back.
2. Receive a **real email** notification locally (via Mailtrap).

Run everything in **Git Bash**. Both stacks must be running.

---

## Part 0 — Start the stacks

```bash
# Terminal 1
cd cloudfile-reference/cloudfile-platform
docker compose up --build

# Terminal 2
cd cloudfile-reference/notification-service
docker compose up --build
```

## Part 1 — Upload an image

### 1. Pick an image and note its size
```bash
cd cloudfile-reference/cloudfile-platform
cp /c/Users/<you>/Pictures/cat.jpg ./cat.jpg     # use any real image path
ls -la cat.jpg                                    # note the byte size, e.g. 45231
```

### 2. Login and capture a token
```bash
curl -s -X POST http://localhost:8001/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"me@example.com","password":"password123","full_name":"Me"}' >/dev/null

TOKEN=$(curl -s -X POST http://localhost:8001/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"me@example.com","password":"password123"}' \
  | grep -o '"access_token":"[^"]*"' | sed 's/"access_token":"//; s/"//')
echo "$TOKEN"
```

### 3. Ask for an upload link (set the real size + image type)
```bash
RESP=$(curl -s -X POST http://localhost:8002/api/v1/files/upload \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"filename":"cat.jpg","content_type":"image/jpeg","size_bytes":45231}')
echo "$RESP"
FILE_ID=$(echo "$RESP" | grep -o '"file_id":"[^"]*"' | sed 's/"file_id":"//; s/"//')
UPLOAD_URL=$(echo "$RESP" | grep -o '"upload_url":"[^"]*"' | sed 's/"upload_url":"//; s/"//')
```
> Use `image/png` for .png files. The size can be approximate for LocalStack;
> for real S3 it should match.

### 4. Upload the actual image bytes
```bash
curl -X PUT "$UPLOAD_URL" -H "Content-Type: image/jpeg" --data-binary @cat.jpg
```

### 5. Confirm (marks ready + sends a notification)
```bash
curl -s -X POST http://localhost:8002/api/v1/files/confirm \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d "{\"file_id\":\"$FILE_ID\"}"
# expect "status":"ready"
```

### 6. Download it back and verify
```bash
DL=$(curl -s "http://localhost:8002/api/v1/files/$FILE_ID/download" \
  -H "Authorization: Bearer $TOKEN" \
  | grep -o '"download_url":"[^"]*"' | sed 's/"download_url":"//; s/"//')
curl -s "$DL" --output downloaded-cat.jpg
ls -la downloaded-cat.jpg      # same size as cat.jpg = success
```
Open `downloaded-cat.jpg` — it's your image.

> Any file type works the same way: text (`text/plain`), images
> (`image/jpeg`, `image/png`), video (`video/mp4`). Max size is 100 MB.

## Part 2 — Receive a REAL email (Mailtrap, free)

By default notifications are only logged. Turn on real email with Mailtrap.

### 1. Get Mailtrap SMTP creds
Sign up at https://mailtrap.io → Email Testing → My Inbox → SMTP Settings →
copy Host / Port / Username / Password. (Full guide:
`notification-service/docs/05-real-email-setup.md`.)

### 2. Restart notification with SMTP enabled
```bash
cd cloudfile-reference/notification-service
export NOTIFICATION_PROVIDER=smtp
export SMTP_HOST=sandbox.smtp.mailtrap.io
export SMTP_PORT=2525
export SMTP_USERNAME=<mailtrap username>
export SMTP_PASSWORD=<mailtrap password>
docker compose down
docker compose up --build
```

### 3. Trigger an email
Either upload+confirm a file again (Part 1 step 5), or send one directly:
```bash
curl -X POST http://localhost:8004/api/v1/notifications/notify \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"recipient":"me@example.com","subject":"Your file is ready","message":"Hello from CloudFile","channel":"email"}'
```

### 4. See it
Open your **Mailtrap inbox in the browser** — the email is there. Service logs
show `notification_smtp_sent`.

> Mailtrap sandbox captures all mail into your inbox; no real person is emailed.
> For production real email to actual inboxes, use AWS SES (see
> `notification-service/docs/05-real-email-setup.md`, Option B).

## What about thumbnails for images?

A **thumbnail** is a small preview of an image (e.g. 256×256). It's generated by
the processor Lambda when a file lands in S3.

- **Locally:** the Lambda isn't running (LocalStack free tier), so no thumbnail
  is created. Your image still uploads and downloads perfectly.
- **Production:** works if the Lambda has the Pillow library (via a layer).

To generate thumbnails locally, the processor can be run as a container — ask
and this can be added.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `401` on upload | token missing/expired — login again, re-set `$TOKEN` |
| presigned PUT signature warning | LocalStack is lenient; the object still stores |
| no email in Mailtrap | check `NOTIFICATION_PROVIDER=smtp` and SMTP creds; restart compose |
| `404` on confirm | wrong `file_id` — re-copy it from the upload response |
