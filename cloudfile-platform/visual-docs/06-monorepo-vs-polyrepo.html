Monorepo vs Separate Repo

CloudFile uses both patterns on purpose. Press Play to watch a request cross the boundary between them.

📦

Monorepo (platform)

auth, files, search in one repo. Shared code via shared/, one Docker Compose, one CI matrix. Easy atomic changes across services.

🧩

Separate repo (notification)

Its own repo, CI, and deploy. Self-contained (own copies of logging/JWT) so it depends on no other repo. Models a team-owned service.

🔗

How they connect

Over the network: files calls notification with httpx, forwarding the user's JWT. Same shared secret → tokens verify on both sides.

Interview line: "Monorepo vs separate repo is a code-organization choice, not an architecture one. The runtime is identical — independent containers talking over HTTP. I used both to show I understand the trade-offs."
