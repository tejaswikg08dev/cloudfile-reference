Local Deployment with Docker Compose

Press Play to watch the whole stack boot — containers start, health checks turn green, and the two repos connect.

Postgres LocalStack (S3) auth files search notification (separate repo)

The commands

# Terminal 1 — core services (monorepo) cd cloudfile-platform cp .env.example .env docker compose up --build # auth:8001 files:8002 search:8003 +pg +localstack # Terminal 2 — notification service (separate repo) cd notification-service cp .env.example .env docker compose up --build # notification:8004 # Terminal 3 — end-to-end demo cd cloudfile-platform bash scripts/e2e-demo.sh
Why two Compose projects? The monorepo and the notification service are separate repos, so each has its own docker-compose.yml. The files service reaches notifications via host.docker.internal:8004 — the notification container publishes port 8004 on your host, so the bridge works across projects.
