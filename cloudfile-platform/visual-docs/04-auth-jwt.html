Authentication & JWT

How a token is issued and how every service verifies it — locally, with no round-trip to auth.

A JWT has three parts

header.payload.signature # header { "alg": "HS256", "typ": "JWT" } # payload { "sub": "<user_id>", "email": "me@example.com", "exp": 1699999999 } # signature = HMAC_SHA256(header.payload, JWT_SECRET_KEY)
Why verify locally? Every service shares the same JWT_SECRET_KEY, so it can validate the signature and expiry itself — no network call to auth on every request. Trade-off: rotating the secret means redeploying all services together.
